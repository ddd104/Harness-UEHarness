# Agent Workbench：Codex 实现任务包

本文档包用于指导 Codex 在你的 UE 工程中实现编辑器插件，不是已实现或已编译验证的 UE 插件。

## 使用方式

1. 将本包的 `Docs/AgentWorkbench/` 放到工程根目录。保留已有文件，发生同名冲突时先比较，不要直接覆盖。
2. 在能够访问该工程的 Codex 工作环境中，发送 `Docs/AgentWorkbench/PROMPTS.md` 的“首次启动提示词”。优先使用能够访问目标 UE 引擎头文件和编译工具的本地环境。
3. 首轮完成工程勘察和 P1。后续按 `TASKS.md` 逐阶段推进，不要一次实现全部模块。
4. `AGENTS.snippet.md` 是要合并到已有项目规则中的片段，不要用它替换原有 `AGENTS.md`。首次提示词会要求 Codex显式读取该片段；不能假设会话中新增文件会自动重新加载。
5. 以实际构建日志、测试结果和编辑器操作结果验收，不能把“已生成代码”当成“编译通过”或“功能验证通过”。

## 文件用途

| 文件 | 用途 |
|---|---|
| SPEC.md | 完整需求、固定布局、候选资产、Session/Run 隔离、设置与安全约束 |
| TASKS.md | P0 至 P6 的分阶段目标、范围和退出条件 |
| PROMPTS.md | 首次启动、继续阶段、候选区专项、修复与终验提示词 |
| ACCEPTANCE.md | 自动化和编辑器内手工验收清单 |
| AGENTS.snippet.md | 精简的长期工程规则 |
| PROGRESS.md | 真实进度模板，所有功能初始均未实现、未验证 |
| REFERENCES.md | 官方 API 与 Codex 文档，接口签名仍以本地目标 UE 版本为准 |

## 本次新增需求

保持“左侧历史 / 中间对话 / 右侧执行详情”的三栏布局。
在中间栏对话记录和用户输入之间，增加“候选资产”面板。
用户在主 Content Browser 选择一个或多个 /Game/ 资产，然后在指定 Agent 窗口中显式点击“添加选中资产”。
候选行只显示完整 Object Path 和右侧 X。X 只移除该窗口所属 Session 的引用，不自动发送请求、不复制或修改真实资产。
发送消息时，将当前候选资产的路径与元数据复制为不可变 Run 快照。

## 首版范围

首版工具只读。先用 Mock Provider 验证完整工作流，再接入真实模型。
实际 API 服务商、模型名称和 UE 小版本没有在本任务中指定，必须从现有工程和用户配置中确认，不能伪造。
如果项目没有既有服务协议，首个真实适配器按明确的 Chat Completions 兼容协议实现，并注明只支持已实现、已测试的协议能力。
不默认把所有服务商都视为兼容，不硬编码某个模型名称，不要求真实 Key 才能调试界面。

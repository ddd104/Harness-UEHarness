# 可直接交给 Codex 的提示词

在工程根目录准备好本包的 Docs/AgentWorkbench 文件后，使用下列提示词。每次只推进一个阶段。

## 1. 首次启动提示词

```text
请在当前 Unreal Engine 工程中实现 Editor-only 插件 AgentWorkbench。
先读取当前适用的 AGENTS.md，再显式读取：
- Docs/AgentWorkbench/AGENTS.snippet.md
- Docs/AgentWorkbench/SPEC.md
- Docs/AgentWorkbench/TASKS.md
- Docs/AgentWorkbench/ACCEPTANCE.md
- Docs/AgentWorkbench/PROGRESS.md

以 SPEC.md 为功能和 UI 的验收依据。AGENTS.snippet.md 是长期规则片段，适合时合并到现有规则的单独章节，保留既有内容；不要假定本轮新增规则会被自动重载。

本次只执行 P0 和 P1：先勘察工程，再落地插件骨架、工具栏新建按钮、多独立窗口、三栏 Slate 布局和项目设置。不要只写设计文档后停止。

特别注意：中间栏必须是“模型栏→对话记录→候选资产区→输入框”，候选区首轮保留真实 Widget 和空态。不能变成单例窗口、单个固定 DockTab、网页面板或只有一个大文本框。

先检查 git status，不覆盖已有未提交改动。确认 .uproject、目标 UE 版本、引擎目录、Editor Target 和实际构建命令。
关键 UE API 必须查本地对应版本头文件/调用示例；网络示例的签名不能直接假定适用。
未能确定引擎或无法编译时记录具体阻塞，继续完成能够完成的实现和静态检查，不编造测试结果。

优先使用 Mock，不接真实 Key，不添加任意写工具、不改引擎源码、不修改无关模块。
每个新窗口创建不同 SessionId，消息、模型和草稿独立；候选列表也必须设计为 Session 数据。

实施后运行可用构建和测试，检查 diff，更新 PROGRESS.md。
最后分别汇报：改动文件、实际执行命令、编译结果、测试结果、编辑器内已验证/未验证项、剩余问题和下一阶段。
```

## 2. 通用继续阶段提示词

把 P2 替换为这次实际要执行的阶段编号。

```text
继续 AgentWorkbench。本次只执行 TASKS.md 的 P2，以及完成 P2 必需的修复。
重新读取适用的 AGENTS.md、SPEC.md、TASKS.md 和 PROGRESS.md，再检查当前代码及 git diff，不要根据前一轮文字汇报推测实现状态。
保持现有三栏布局和已通过验收的功能，不扩展到后续阶段。
先实现最小可验证改动，补充对应自动化测试，实际运行可用的构建/测试。
更新 PROGRESS.md，报告文件、命令、结果及未验证项。没有真实运行的检查不可标为通过。
```

## 3. 候选资产区专项提示词

适合已有原版窗口实现、现在只追加用户新增需求的情况。

```text
请在当前 AgentWorkbench 插件中新增“候选资产”功能，不重新设计已有三栏布局。

UI 位置：中间栏的对话记录下方、用户输入框上方。实现独立 SAgentAssetCandidatePanel。
候选面板有：添加选中资产、清空、折叠、条目勾选、完整对象路径、复制路径、定位、移除。
新条目默认启用；候选多时内部滚动，不把输入框挤出窗口。

交互：
用户在 Content Browser 中多选蓝图，回到指定 Agent 窗口点击“添加选中资产”，仅向该窗口的 Session 追加引用。
不是 World Outliner 的 Actor 选择。选择变化不自动添加，更不能自动发送给模型。
读取主 Content Browser 选择，并按当前 UE 版本验证多个 Content Browser 的来源行为，Tooltip 明确来源。
过滤默认 /Game/ 蓝图及可识别的蓝图子类，按真实资产类型判断，不能依赖 BP_ 名称。
按规范化完整对象路径去重；显示新增、重复、跳过数量。
清空和移除只处理会话引用，严禁删除、保存、重命名、复制或编译真实资产。

数据和执行：
Session 保存 CandidateAssets。每项含 CandidateId、DisplayName、ObjectPath、PackageName、AssetClassPath、bIncluded、ValidationStatus。
通过目标版本的 FAssetData.GetSoftObjectPath 等接口取得引用；不用磁盘绝对路径、UObject 指针或无条件拼接 _C。
获取选择和展示候选时只使用轻量元数据，不因 UI 刷新加载所有蓝图。
发送消息时复制已勾选资产为当前 Run 的不可变快照；模型请求中包含这些资产的真实路径，右侧模型输入预览可见。
运行中修改候选只影响下一次发送。工具必须从 Run 快照取资产，不再读取当前编辑器选择。
取消勾选不表示已经撤回历史中发送过的内容，UI 文案要准确。

历史：
保存与恢复候选路径、勾选状态和显示信息；不直接序列化 FAssetData 或运行时对象。
资产失效时保留条目并提示重新选择；注册表尚未就绪不能误报删除。
分叉会话复制候选值，新旧会话后续修改独立。

先检查现有代码和本地引擎 API，再实施最小改动并补测试。
至少验证：多选、追加去重、无选中、非蓝图、A/B 会话隔离、快照不随选择改变、移除不删除资产、历史恢复、失效路径、完整路径进入模型请求。
实际运行可用构建/测试；没有执行的编辑器操作标为未验证。输出改动文件、命令、结果和遗留项。
```

## 4. 修复构建或回归提示词

```text
本次只修复下面的编译错误或可复现回归，不重构整个插件、不改已确认布局。
先读取 SPEC.md 和相关代码，根据实际调用链定位原因，给出最小修复。
UE API 签名以本地目标引擎版本为准，不通过删除功能、注释关键逻辑或返回假成功来绕过错误。
修复后重跑对应构建与最小回归测试，检查是否影响 Session/Run/候选资产隔离。
更新 PROGRESS.md，明确实际验证结果。

下面附上实际命令、首个关键错误及上下文、复现步骤：
[在此粘贴真实日志和操作步骤]
```

## 5. 最终审查提示词

```text
审查并验收当前 AgentWorkbench 实现，按 SPEC.md 和 ACCEPTANCE.md 逐条对照。
先做问题清单，不新增需求；必要修复以最小改动完成。

重点检查：
1. 一个按钮重复点击是否真的创建多个独立 Session 和非模态窗口。
2. 消息、模型、草稿、候选、请求、工具调用和取消是否归属正确。
3. 候选是否来自 Content Browser 而非 Actor 选择；是否只在目标窗口显式添加。
4. 是否按真实对象路径去重；移除是否仅删除引用。
5. 模型请求是否实际携带启用候选，工具是否使用发送时快照而非实时全局选择。
6. 取消、超时、排队、迟到/重复回调、关闭/退出是否污染其他任务或悬空访问。
7. 历史是否恢复候选和模型，是否错误重放工具，是否会改写旧 Run 快照。
8. 是否记录密钥、Authorization、环境变量值或其他凭据。
9. 是否后台线程访问 UObject、存在强引用环、无上限的工具循环或日志。
10. 是否有看似完成但仍是 Mock、TODO、空回调、伪造数据的真实功能。

运行当前环境支持的构建和测试。报告真实命令和结果。
每项分类为“已验证通过 / 失败 / 代码已实现但未验证 / 未实现”，并给出依据。
未执行的编辑器验收、无 Key 的真实 API 集成，不能标成通过。
输出尚未满足的条目及具体文件位置，不把整个插件笼统标为完成。
```
